# PC 浏览器审查与修改建议

审查基线：原仓库 main 的 c2f7bfd（2026-10-26）。范围为静态单机网页与 PC 浏览器；手机布局暂不列入本次修改。

## 本 PR 修复的安全问题

大富翁和棋盘巡礼允许输入玩家昵称，部分界面把昵称直接拼入 innerHTML。昵称中的标签会被当作 HTML 解析；事件属性还可能执行同源脚本。赛前切换人数重新绘制输入框时，昵称也能逃出 value 属性。

目前昵称来自同机手动输入，没有发现通过 URL、网络或存档导入昵称的入口，因此属于本地输入触发的 HTML 注入 / self-XSS 风险，不应描述为可从远程直接攻击电脑。

补丁保留原始昵称，不在输入或状态层删字符：

- 赛前输入框通过 value 属性赋值。
- 事件横幅的图标、标题与描述通过 textContent 赋值。
- 仍使用 HTML 模板的玩家面板、顶部栏、地块归属、查经标题、目标选择与结算名单，在显示昵称时转义 &、<、>、双引号和单引号。
- 棋盘巡礼的玩家名册和结算名单补上同样的转义。

不新增依赖，不改变题库、角色数值、胜负判定或电脑策略。

参考：[MDN innerHTML 安全说明](https://developer.mozilla.org/en-US/docs/Web/API/Element/innerHTML#security_considerations)。

## 功能提醒与建议（本 PR 未修改）

### 1. 电脑购买恩赐后不会使用

位置：dafuweng/game.js 的 handlePentecostTile、enterReadyRollPhase。

电脑会花信心兑换恩赐，但准备投骰时直接进入 executeRollDice，没有电脑发动恩赐的流程。电脑会损失信心并逐渐塞满卡槽。

低成本建议：暂时让电脑跳过付费兑换，并在界面说明电脑暂不使用恩赐。后续再增加电脑使用技能的策略；涉及目标选择的技能不能直接复用真人弹窗，否则会等待人工操作。

### 2. 题库加载与开局存在竞态

位置：loadQuestionsJSON、startNewGame、getRandomQuestion。

加载是异步的，而开局按钮立即可用。如果玩家在加载完成前开局，activeQuestionPool 会复制一个空数组；之后加载成功也不会更新该局题池，每次问答都退回同一道备用题。

建议：读取期间禁用开局按钮；成功加载或明确切换到备用题库后再启用。非数组、空数组或题目结构无效也应走统一的失败处理，并明确告知使用的是备用题库。不要在游戏中途静默切换难度或题池。

### 3. 获胜者与最终排名可能不一致

位置：checkVictoryConditions、showGameOverModal。

信徒目标模式按最先达到目标判定获胜，但结算列表对所有模式都按综合分排序，因此获胜者可能被排在第二名。

建议：结算第一位固定为实际获胜者，并标注获胜原因；其他名次按当前模式的规则排序，只有限时积分制把综合分作为主要排名依据。

## 复核方法

- 使用包含中文、&、单双引号及 <b> 标签的昵称：界面应原样显示文本，切换人数后输入值也应保留。
- 使用带事件属性的测试昵称：开始游戏、渲染归属、弹出横幅或结算时，不应产生注入的元素或执行事件。
- 检查所有昵称流向 HTML 的位置，避免只修玩家面板而遗漏横幅、输入属性或结算名单。
- PC 基本流程已在原版试玩：开局、投骰、建堂扣款、回合切换、安息日恢复、晨更答题；未完整跑完 40 回合或覆盖所有角色与恩赐组合。

## 本补丁的验证结果

`node --test tests/player-name-security.test.js`：3 项通过。

检查直接调用两个游戏的真实渲染函数，使用轻量 DOM 替身核对输出，覆盖输入框 value、横幅 textContent、玩家面板、顶部栏、地块归属、问答标题、目标选择及结算名单。测试昵称包含中文、单双引号、&、标签和事件属性。该检查不等同于完整浏览器端到端测试。
